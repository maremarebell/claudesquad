# Claude Squad site

Static site for Claude Squad (NYC fitness + computing crew). React 19 pages built to static HTML by Eleventy (11ty) v2, one hand-written stylesheet (type sizes are the `--text-*` rem scale in `:root`), no bundler and no build step beyond 11ty itself. Markup is `htm` template strings (`html\`...\`` from `src/js/ui.js`), not JSX, so the same component files run in Node at build time and in the browser from the importmap. Every page is a component in `src/pages/*.mjs` that 11ty renders to a full document: `.eleventy.js` registers `mjs` as a template format and runs `scripts/render.mjs` in a fresh Node process per page, so an edited component shows on the next build even under `eleventy --serve`. The parts that run in the browser are islands: `Island` in `src/_includes/layout.mjs` renders a component into an element with `data-island` (its module name; `board.js` exports `Board`) and `data-props` (JSON), and `src/js/mount.js` hydrates each one with the same props plus `host`, the element itself. A component's first render reads nothing from the browser (no `localStorage`, `matchMedia`, `document`), so it matches the markup the build made; what the browser knows comes in effects. Pages without islands (members, profiles) load no React at all. React and htm in the importmap are the versions in `package.json` (`test/build.test.cjs` checks, and renders every page in memory).

## Commands

```
npm install
npm run dev     # eleventy --serve (live reload)
npm run build   # outputs to _site/
npm test        # unit tests (node --test, no dependencies); CI runs them + a build on every push/PR (.github/workflows/test.yml)
```

Tests live in `test/`. Logic is kept out of DOM/network code so it can be tested: pure rules go in `src/js/checkin.js` (check-in), `src/js/format.js` (text) and `server/rules.mjs` (validation, CORS, connection); the calendar and next-meetup builders (`buildMonths` in `src/js/calendar.js`, `pickNext` in `src/js/meetup.js`) and `reposFrom` in `src/_data/prRepos.js` are pure. `test/data.test.mjs` also validates `events.json` and the profile/project/gallery front matter, and `test/pig.test.mjs` fails if the three pig bitmap copies drift.

## Structure

- `src/pages/home.mjs` — homepage: 3D hero (`src/js/hero.js`, raw three.js, attaches to the rendered markup; the `.hero__tag` it writes stays outside any island) with the next meetup overlaid (`src/js/meetup.js`: `pickNext`/`formatDate` and the `meetup` island, re-picked in the browser by New York's date), intro copy, the leaderboard (`board` island), photo gallery (sorted by date, newest first). Without WebGL the flat `logo.jpg` shows instead.
- `src/_includes/layout.mjs` — `Layout`, the shell every page renders into (head, header + nav with `aria-current`, WhatsApp topbar, footer, the importmap, `site.js` + `mount.js`), and `Island`. `src/js/site.js` is the plain per-page script (service worker, console greeting, footer tilt, nav says Check in when a session exists).
- `src/pages/here.mjs` + `src/js/here.js` — `/here/`, login + check-in against the check-in server (`site.apiUrl`). The whole panel is the `Here` component (the `here` island; props `repo`, `branch`, `apiUrl`, `prRepos`, `events`), so the join form is in the markup before React loads; the page also carries a classic inline script that replaces "Loading…" if React never arrives. `here.js` is that one component: the screen is React state (`flags` are also the root's `here--*` classes, which the CSS and motion-debug read), while the bump itself (shake listener, location, the re-sending loop) is async code reading refs (`userRef`, `flagsRef`, `checkingIn`), so a render mid-loop changes nothing. Join = name + GitHub username, session token in localStorage; a username already in the squad signs in as that member from any phone (only a login GitHub has verified, through Sign in with GitHub, is refused and sent to GitHub); Sign in with GitHub appears when the server has GitHub OAuth env vars. The home-screen app on iPhone keeps storage apart from Safari, so it signs in two other ways: "Sign in somewhere else" on a signed-in phone shows a one-time code (10 minutes) to type under "Sign in with a code", and Sign in with GitHub from the installed app sends a nonce (`?app=`) and polls `POST /api/auth/claim` for the session, since GitHub's redirect lands in Safari, not the app (`handoffs` table). Check-in is a Bump: on a meetup day a pixel pig (SVG, same bitmap as the hero) waits; tap arms motion and follows the location (`watchPosition`, so the bump never waits on a GPS fix), 3 shakes POST `/api/bump` (how hard a shake must be adapts per phone: `shakeCounter` in `checkin.js` learns from recent jolts, near misses and resting jitter, kept in `localStorage['squad-shake']`; signing in by typing reloads the page so iPhone's shake-to-undo has nothing to offer), and bumps within 20s and 250m of each other check everyone in, any number at once (server-side, the only way a check-in row is written). With no match the phone re-sends every 2s for 30s (`WAIT_MS`), riding out dropped requests, then reads the board for 20s more (`LATE_MS`) in case a partner shook in late against its last bump. After the first match the phone keeps the group open, re-sending until 6s pass with nobody new (`GROUP_MS` in `here.js`), so later phones land on every screen; `collide.js` brings in up to 8 faces. Haptics go through `buzz` (patterns in `HAPTIC`): Android `vibrate()`, iPhone a hidden switch checkbox ticked once per "on" (`tapsOf`). Someone already in can bump a newcomer in. Tap works instead of shaking when motion is denied or silent. Motion debug checkbox under the button (remembered in `localStorage['squad-debug']`) pins `src/js/motion-debug.js` top left: raw axes, jolt vs this phone's current bar (`shakeBar`), event rate, counted jolts and a 3s graph, listening on its own so it works on any day. First check-in shows an "Add yourself on GitHub" card. Points (also on the homepage leaderboard): 1 per check-in on an `events.json` date + 1 per merged PR to this repo or a Projects repo (`src/_data/prRepos.js`), counted in the browser from GitHub's public search (10-minute cache) and matched to members by GitHub login; the rules are `POINTS`/`countPRs`/`leaderboard` in `checkin.js`.
- `server/` — the check-in server: plain Node `http` + `pg`, schema in `server/schema.sql` (applied on every start, create-if-missing). Routes are listed at the top of `server/index.mjs`; their input rules (validation, sign-in codes and app nonces, CORS, connection) are in `server/rules.mjs` (`test/server-rules.test.mjs`). `server/e2e.mjs` tests it against a local Postgres in Docker, including Sign in with GitHub against `server/mock-github.mjs`, a stand-in for GitHub's OAuth endpoints; the server points at it through `GITHUB_URL` and `GITHUB_API_URL` (defaults: github.com), which is also how to try the GitHub button on a laptop (`node server/mock-github.mjs`, then run the server with those two plus any `GITHUB_CLIENT_ID`/`GITHUB_SECRET` and `RENDER_EXTERNAL_URL=http://localhost:10124`).
- `src/js/hero.js` lifecycle (reduced motion, background tabs, lost WebGL context falling back to the flat logo, ring framing at phone and desktop widths) is covered by `test/hero.test.cjs`, which runs the file against stubs, no GPU.
- `src/js/checkin.js` — the pure rules (New York date, tally, meetup lookup, jolt, adaptive shake counter), tested by `npm test` (`node --test`, no dependencies). `squad.js` (API client retries, sign-out, PR cache) and `src/sw.js` are tested against stubs in `test/squad.test.mjs` and `test/sw.test.cjs`.
- Scripts are served from `/js/<version>/` (the `js` prop every page gets; `jsVersion` in `.eleventy.js` hashes `src/js/`), so a page's module imports all come from one build even while the CDN still holds older copies of some files after a deploy. Always load page scripts as `${js}/name.js`, never `/js/name.js`; the plain `/js/` copy only serves pages cached from before a deploy. The CDN ignores query strings, so `?v=` would not bust it.
- `src/manifest.webmanifest` + `src/sw.js` — PWA, starts at `/here/`. The worker is network-first and same-origin only.
- `src/pages/calendar.mjs` + `src/js/calendar.js` — calendar page, entirely data-driven: `buildMonths(events, today)` and the `Calendar` island (see below)
- `src/js/pig3d.js` — the 3D check-in pig as a React Three Fiber `<Canvas>` (voxels from `src/js/pig.js`): idle breathing and turn, hop per shake (`rep` prop), spin + voxel confetti on a match (`celebrate` prop), lies down asleep on non-meetup days (`sleeping`), drag to turn. The pose each frame is the pure `src/js/pigpose.js` (`test/pigpose.test.mjs`). `React.lazy`-loaded by `here.js` once someone is signed in, only where a WebGL context can be made and motion isn't reduced; the SVG pig stays otherwise. The loop stops off screen (`frameloop` demand). Sections swing up in 3D as they enter; the footer slab is extruded with text-shadows and tilts to the pointer or phone tilt.
- Motion: the hero pig assembles from flying voxels on load (`placePig` in `hero.js`), scrolling blows it apart, tips it back and pulls the camera away; reduced motion shows it whole. On a /here/ match `src/js/collide.js` smashes both faces together (`onImpact` times the buzz). Pages morph with cross-document View Transitions (`@view-transition` in `styles.css`). Sections swing up in 3D as they enter; the footer slab is extruded with text-shadows and tilts to the pointer or phone tilt.
- `src/js/squad.js` — shared by every page that talks to the server: `API` (`site.apiUrl` via `<meta name="squad-api">`, or `http://localhost:10124` when the site runs on localhost; empty in the build), the session token (`localStorage['squad-token']`), `api()`, `mergedPRs()`, `REDUCED`, and `el()`/`avatar()` for `collide.js`. `src/js/ui.js` has what the components share: `html`, `Avatar`, `useCountTo`, `useToday`.
- Homepage leaderboard (`#board`, `src/js/board.js`, the `board` island): public, `GET /api/leaderboard` + GitHub PR counts, bars grow when on screen, refreshes every 30s.
- `/admin/` (`src/pages/admin.mjs` + `src/js/admin.js`, not in the nav, noindex): a Partiful field per meetup; Save copies the updated `events.json` and opens it in GitHub's editor. GitHub decides who can commit it.
- `src/pages/projects.mjs` — `/projects/`: "What are you working on?" (`src/js/working.js`, the `working` island; members post a line + optional link via `POST /api/posts`, everyone reads `GET /api/posts`, authors can delete), then everything in `src/projects/*.md` (front matter `name`, `repo`, `lead`, `help` list; body is the description). `projects.json` sets `tags: project`, `permalink: false`. Each links to the repo's issues and its `good first issue` ones; "Add a project" opens GitHub with the file started.
- `src/pages/members.mjs` — `/members/` index, lists everyone in the `profile` collection (photo, name, role) linking to their page
- `src/profiles/*.md` — one file per person; filename *is* the URL slug (`mare-co-captain.md` → `/members/mare-co-captain/`). Shared data comes from `src/profiles/profiles.11tydata.js` (11ty directory data file: `layout: profile.mjs`, `tags: profile`, the permalink computed from `page.fileSlug`)
- Pages name the collections they use in their `data` export (`uses: ['profile']`); `.eleventy.js` hands each over as plain JSON (`profiles`: `url`, the rendered `content`, and the front matter fields listed in `FIELDS`). Add a field there when a page needs a new one.
- `src/gallery/*.md` — one file per photo, front matter only (`image`, `date`, `event`, `caption`). `src/gallery/gallery.json` sets `tags: photo`, `permalink: false` (these don't render their own pages, just feed the `photo` collection)
- `src/_includes/layouts/profile.mjs` — the member page (photo circle, name, role, bio): the 11ty layout the Markdown profiles render through, given the front matter and the rendered body as props.
- `src/css/styles.css` — the only stylesheet, plain CSS with custom properties, BEM-ish class names (`.calendar__day--event`, etc.)

### `src/_data/` (11ty global data)

- `site.json` — `{ whatsappLink, repo, apiUrl, branch }`. `apiUrl` is the check-in server. `branch` is the branch Render deploys; every "add/edit on GitHub" link (profile, project, Partiful admin, CONTRIBUTING) targets it, so submissions land where the live site builds from. Change it to `main` together with Render's branch once PR #1 merges. Currently always set to a real invite link; there's no "link missing" fallback anywhere anymore (it was removed on purpose — see git log "Remove the no-link fallback for the WhatsApp button"). If this ever needs to go back to being optional, that pattern would need re-adding in `src/_includes/layout.mjs`.
- `events.json` — the single source of truth for all meetups. Each entry: `date` (`YYYY-MM-DD`), `title`, `emoji` (optional), `color` (optional, defaults to `var(--accent)`), `partiful` (URL or `null`). This is the file to edit when meetups are added/changed — nothing else needs touching.
- The calendar grid is `buildMonths` in `src/js/calendar.js` (not a data file, since the browser runs it too), computed *from* `events.json` with a `today` string: the build machine's date, then New York's date in the browser. Key behavior: it only renders 3-month blocks for quarters that actually contain an event (sorted chronologically), **not** a rolling window based on today's date. The next quarter only appears once an event is added to it — this was an explicit user request, don't "fix" it back to date-based rolling. Falls back to today's quarter if `events.json` is ever empty. Also marks `isPast` per month (fully-elapsed months) for the gray-out/mobile-hide behavior in CSS.
- The next meetup is `pickNext` in `src/js/meetup.js`: the soonest event on/after today, for the homepage hero; the browser re-picks it by New York's date (the build can be days old) and the calendar re-marks today and past months the same way. `null` when nothing is upcoming (the panel is hidden).

## Design system

- Colors (`:root` in `styles.css`): `--site-bg: #000000` (sampled exactly from `logo.jpg`'s background — keep it pure black, don't drift back to `#0b0b0b`), `--accent: #d9835f` (terracotta from the logo), `--ink` / `--ink-muted` for text, `--card-bg` / `--border` for panels.
- Fonts: Claude's look. Claude uses Anthropic Serif/Sans/Mono (not open licence), so `--serif` (Source Serif 4), `--sans` (Hanken Grotesk) and `--mono` (JetBrains Mono) stand in, each listed after the Anthropic name so a machine with the real font uses it. Serif for h1/h2, the hero wordmark and calendar months; sans for body; mono uppercase for small labels. `Press Start 2P` (`--pixel`) stays only for brand bits: header wordmark, tagline, footer mark, points, the Friendshipmog button.
- Look: industrial/terminal. No border-radius anywhere (reset sets it to 0), 1px `--rule` hairlines to divide things, `.ticks` for corner registration marks, `<mark>` for the accent highlighter that swipes in on scroll. Two page-height hairlines live on `.page::before`. No section numbers or noise grain (dropped on purpose).
- Layout: spacing comes from the `--space-*` scale in `:root` (3xs 4px to 2xl fluid), never raw px. `--gutter` lines page content up just inside the two page hairlines (6vw + 24px, 16px on phones, where the hairlines hide). `.content` and `.gallery` are two-column sections: sticky heading left, material right, a rule between sections. Stacking uses `--z-scene/--z-overlay/--z-tooltip/--z-chrome`.
- Small rewards: clicking the hero canvas (or Enter/Space when it has focus) makes the pig do a rep (corner tag counts reps); on `/here/` each counted shake is a pig rep plus a filled pip, and a check-in bursts pixels and pixel hearts off the pig, bigger at 5/10/25/50/100 meetups. No pause-motion control (the user said no); reduced motion is the off switch. Buttons are square accent blocks that invert to `--ink` on hover.
- Profile pictures: every one is a square with `--face-frame` (2px accent), in colour (no grayscale, which would gray the frame); the small ones (leaderboards, posts, today's faces) are all `--face` (40px). The pig stands in when GitHub has no picture.
- `h1`/`h2`/`.page-title` all share the serif look; keep new headings consistent with that.
- Icons are drawn from the pig bitmap by `python3 scripts/icons.py`: `src/images/pig.svg` (header and SVG favicon), the PNG favicons and `favicon.ico`, and the home-screen icons (dark pig on the accent, inside the maskable safe zone). The bitmap is `PIG` in `src/js/pig.js` (the check-in page and the 3D pig import it), copied in `hero.js` and `scripts/icons.py`; change all three together (`test/pig.test.mjs` fails if they drift). `logo-840.png` (hero fallback) is a 16-colour PNG from `logo.jpg` (ffmpeg `palettegen`/`paletteuse=dither=none`). three.js is the minified build, with both files `modulepreload`ed by `src/pages/home.mjs` so they download in parallel.
- Images: `src/images/logo.jpg` is the full lockup (pig + "MAKE NO MISTAKES" tagline) used in the homepage hero. `src/images/logomark.jpg` is the cropped pig-only mark used in the header and as the favicon source. `src/images/favicon/` comes from `scripts/icons.py`.

## Content model

- Profiles live under `/members/slug/` and are listed on `/members/`.
- `CONTRIBUTING.md` has the full user-facing instructions for adding a meetup, a profile, or a gallery photo via PR — keep it in sync if the data shapes above change.
- Git: remote is github.com/maremarebell/claudesquad.
- Deploy: Render, all free. Static site `claudesquad` (live at https://claudesquad.org; made in the dashboard, builds `main`; Render's CDN caches each file for 5 minutes, `s-maxage=300`), plus the Blueprint in `render.yaml`: `claudesquad-api` (server/). Its database is Neon project `claudesquad` (`blue-heart-05754755`, us-west-2), connection string in the service's `DATABASE_URL` (set by hand in Render, never in the repo); the server creates its tables in schema `claudesquad` on start. Its `SITE_URL` (where GitHub sign-in returns) is https://claudesquad.org; `allowedOrigins` in `server/rules.mjs` lists the sites allowed to call it. Pushes auto-deploy the static site (seen on 0693e6a). The free API sleeps when idle; `.github/workflows/wake-api.yml` pings it every 10 minutes on `events.json` dates (New York time).
